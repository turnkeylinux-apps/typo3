# TYPO3 v19.0 testing

## Release and source boundary

The v19 appliance uses Debian 13/Trixie for Apache, PHP, MariaDB, cron,
Postfix, Python and the remaining operating-system stack. The compatibility
probe resolved Apache 2.4.68, PHP 8.4.24, MariaDB 11.8.6 and Composer 2.8.8
from Trixie.

Debian does not provide the TYPO3 CMS application. The application therefore
comes from the official TYPO3 Composer packages. The appliance pins TYPO3
13.4.34 LTS and the Introduction Package 4.7.0 in `composer.json` and commits
the complete dependency lock. The lock SHA-256 is
`05ce7f4fa6e485780c31fc482e7388e109d9acfe0b61222c6d9fbfec367092cf`.
Composer verifies the distribution checksums in that lock during installation.

The official TYPO3 major-release API identified 13.4.34 as a security release
on 2026-08-11. Its published tar SHA-256 is
`7bbbac08eb51455b3f6e192826e565acbab1165ba56aea90ce2b541615e5bcf6`.
`/usr/local/share/typo3-release` binds those values to the build and updater.
The focused dependency audit found no security advisories at 13.4.34. It
reported one abandoned transitive package, `doctrine/annotations`, for which
the dependency metadata suggests no replacement.

## Focused runtime test

Run the test as root inside the disposable appliance container after firstboot
has completed:

```sh
TKL_TEST_RESULT=/tmp/typo3-v19.result /usr/local/src/typo3/tests/v19.sh
```

The acceptance harness supplies the actual tracked test path and result path.
The script checks these boundaries:

1. Apache, MariaDB, cron and Postfix are active.
2. The HTTPS frontend loads a local static asset, while Adminer and Webmin
   answer on their documented HTTPS ports.
3. The password supplied to firstboot opens a real TYPO3 `admin` backend
   session, proving the credential inithook and application authentication
   together.
4. A disposable visible page record persists in MariaDB and is rendered by the
   TYPO3 frontend route. The trap removes the record.
5. The installed TYPO3 version and dependency lock validate.
6. The scheduled TYPO3 command exits successfully and the scheduler extension
   is active.
7. `typo3-update --check` reports the installed version, 13.4 LTS channel,
   update status and official tar digest without changing the application.

The standalone Trixie compatibility fixture passed frontend rendering, static
asset delivery, an authenticated backend session, MariaDB page persistence,
public page rendering and scheduler execution on 2026-08-25. A separate
disposable update fixture moved TYPO3 13.4.33 to 13.4.34, ran extension and
database setup, flushed caches, cleared the prior security advisory and then
passed frontend and scheduler checks.
